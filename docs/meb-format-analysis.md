# Анализ файла «для передачи.meb» и вывод о генерации .meb

Дата анализа: 2026-10-24. Файл получен из Google Drive, размер 66 474 байта.

## 1. Что показал побайтовый разбор

Команда: `python3 tools/meb_probe.py "google_drive/для передачи.meb"`

| Признак | Значение | Что это значит |
|---|---|---|
| Первые байты | `2a 44 3f 03 8c fb 00 4d cc f8 08 a3 74 14 e5 ad` | сигнатура `*D?` + версия `0x03` — формат PRO100 нового поколения (5.x/6.x/7.x). В старых файлах (3.x/4.x) в начале лежит открытый текст `PSTO` |
| Энтропия тела файла | **7.9973 бит/байт** | практически максимум (8.0). Так выглядит либо шифротекст, либо сжатый поток; у открытой 3D-геометрии энтропия обычно 5–7 |
| Различных значений байта | **все 256** | равномерное распределение |
| Частота байтов | min 214 / max 299 при среднем 259.6 | идеально ровная гистограмма — признак шифрования/качественного сжатия, а не структурированных данных |
| Нулевые байты | 247 (ожидание для случайных данных — 259.6) | нулей не больше, чем «по случайности» |
| Повторяющиеся 4-байтовые блоки | **0** | нет ни таблиц, ни повторяющихся структур заголовков |
| Печатаемые символы | 37 % | ровно доля «случайных» печатаемых байтов; осмысленных строк нет |
| zlib / gzip / bz2 / lzma | распаковка не удалась ни с одного смещения 0–16 | стандартным сжатием это не упаковано |
| Простые обфускации (XOR одним байтом по всем 256 ключам, ±индекс, XOR индексом, дельта-кодирование) | ни одного попадания | тривиальная «защита» исключена |

Вывод по формату: **полезная нагрузка зашифрована** (вероятно, потоковый/блочный шифр, возможно поверх сжатия). Сигнатура в начале — единственное, что читается без ключа.

## 2. Можно ли создавать такие файлы?

Короткий ответ: **да, но не «с нуля на глазок» — нужен реверс-инжиниринг алгоритма из Pro100.exe.**

Почему:

1. Формат закрытый и недокументированный. Публичных спецификаций `.meb`/`.sto` нет, официальные конвертеры Ecru (mesh.exe, AddTexture.exe) только читают/пишут его сами и не раскрывают структуру.
2. В открытых репозиториях нет ни парсера, ни генератора `.meb` (проверено поиском по GitHub/PyPI/npm — только утилита для счетов из отчёта PRO100, формат там не разбирается).
3. Значит, для генерации нужно:
   - снять дампы с реальных `.meb` (сохранённые элементы одной версии PRO100),
   - найти в `Pro100.exe` подпрограммы шифрования/дешифрования (сигнатура `*D?` — хорошая точка входа),
   - восстановить ключ/алгоритм, проверить на паре «элемент → байты»,
   - и только потом писать свой writer + сверять, что PRO100 открывает результат.

Это отдельный исследовательский проект (дни-недели, нужен Windows с PRO100 и отладчик), и он же юридически серый: реверс закрытого формата и ключей может нарушать лицензию.

## 3. Что работает уже сегодня и поддерживается официально

PRO100 5.20+ умеет **импортировать 3D-модели** через «Файл → Импорт → 3D модель» из форматов **OBJ, 3DS, DAE**. В окне импорта задаются единицы измерения, масштаб, ориентация полигонов (CW/CCW), копирование текстур и папка назначения в библиотеке. После импорта элемент штатно сохраняется в `.meb` уже самой программой.

Поэтому правильный путь к «полноценной библиотеке модулей» — **генерировать OBJ + MTL + текстуры + спецификацию**, а `.meb` пусть делает PRO100. Именно это и реализовано в этом репозитории (`pro100lib`).

## 4. Ограничения пути через OBJ

- Элемент приходит как «голая» геометрия: параметризация PRO100 (размеры, формула, свойства деталей) не переносится — её всё равно задают в редакторе элемента.
- Цвет/текстура назначаются материалом OBJ, но «правильные» материалы PRO100 (прайс, кромка, раскрой) придётся доводить в самой программе.
- Для полноценной параметрики в PRO100 нужен её внутренний редактор элементов; генерация `.meb` дала бы именно его «родные» элементы.

## 5. Что делать дальше (если нужен именно .meb)

1. Собрать эталонную коллекцию: 10–20 `.meb` одной версии, сделанных вручную (простая плита, плита с текстурой, группа, элемент с фасадом).
2. Сравнить дампы: одинаковые элементы, разные имена/размеры → понять, где метаданные, где геометрия.
3. Поставить точку останова на чтении файла в Pro100.exe, найти функцию расшифровки по сигнатуре `*D?`.
4. После восстановления алгоритма — реализовать `pro100lib/format/meb.py` с writer/reader и тестами «побайтовое совпадение с эталоном».
5. Проверить, что PRO100 открывает сгенерированный файл, и только потом строить на этом библиотеку.

Пункты 1–2 можно начать прямо сейчас: скрипт `tools/meb_probe.py` уже даёт отчёт по любому `.meb`/`.sto` и сам покажет, если внутри окажется открытый/сжатый блок.
